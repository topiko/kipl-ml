# Ethan experiment

This directory is a small wrapper around `experiment/ephemeral_defences/` so you can run the same training/eval pipeline using the configs in `experiment/Ethan/config/`.

## Prereqs

- Repo root `.env` must set `MLFLOW_TRACKING_URI` (the underlying pipeline asserts this is present).
- Data must be prepared/converted (see repo root `README.md`).

If you use fixed-machine defences (Breakpad/FRONT/Interspace/Regulator/Tamaraw), you also need `MACHINATION` in `.env`.

## Running

From `experiment/Ethan/`:

```bash
python main.py --config-name=df-multi defence=maybenot defence.deck=/path/to/deck.yaml
```

Notes:

- `--config-name=df-multi` selects `experiment/Ethan/config/df-multi.yaml`.
- `defence=maybenot` selects `experiment/Ethan/config/defence/maybenot.yaml`.
- `defence.deck=...` is forwarded to the wrapped pipeline and is treated as the Maybenot deck path.

## Deck path (Maybenot)

For `defence=maybenot`, the deck file is a YAML file (typically generated by maybenot tooling) that the `mbnt` package can load.

You can pass it in one of these ways:

```bash
# Recommended
python main.py --config-name=df-multi defence=maybenot defence.deck=/abs/or/rel/path/to/deck.yaml

# Equivalent
python main.py --config-name=df-multi defence=maybenot defence.deck_path=/abs/or/rel/path/to/deck.yaml
```

Path resolution is relative to your current working directory.

To preview the fully composed Hydra config without running training:

```bash
python main.py --config-name=df-multi defence=maybenot defence.deck=/path/to/deck.yaml --cfg job
```

## What to expect

- MLflow runs are logged under the MLflow experiment name `Ethan` (from `experiment/Ethan/config/misc/default.yaml`).
- Hydra creates an `outputs/` directory under `experiment/Ethan/` by default.
- The run name is derived from the defence/model settings (see `experiment/ephemeral_defences/main.py`).

## Overview table (MLflow)

This wrapper reuses the table generation logic from `experiment/ephemeral_defences/scripts/overview_table.py`, but defaults to the MLflow experiment name `Ethan` and writes outputs into `experiment/Ethan/tables/`.

From `experiment/Ethan/`:

```bash
python scripts/overview_table.py
```

Or explicitly:

```bash
python scripts/overview_table.py -en Ethan
```

Outputs (written to `experiment/Ethan/tables/`):

- `overview_table_raw.csv`, `overview_table_formatted.csv`
- `table.tex`
- `['Ethan']_table.txt`

## How config composition works

This wrapper does not define any training logic.

- `experiment/Ethan/main.py` is a Hydra entrypoint whose `config_path` is `experiment/Ethan/config/`.
- `--config-name=...` picks the top-level config file in that directory (e.g. `df-multi.yaml`).
- That top-level file contains a `defaults:` list which composes the final config from config groups like:

```yaml
defaults:
  - model: df-multi
  - dataset: bigenough
  - lr_scheduler: cosine
  - optimizer: adamw
  - network: bottleneck
  - defence: no_defence
  - train: default
  - loss: crossentropy
  - misc: default
  - _self_
```

- Command-line overrides (e.g. `defence=maybenot`, `defence.deck=...`) replace parts of that composed config.
- The composed config object is then passed to the underlying pipeline in `experiment/ephemeral_defences/main.py`.
